Security, privacy & useful tools

Account security, personal message backups, reminders, chat organization, and safer sharing. Sensitive operations use your signed-in SPIKE account.

🔐 Two-factor authentication

Set up an authenticator-app TOTP factor through Supabase Auth. Keep your recovery codes safe; this tool does not create or store them.

📦 Message backup

Export private messages available to your account into a local JSON file. The file contains private content; store it securely.

Restore is not written back to the server in this version: re-inserting message history requires a verified server-side restore workflow to avoid spoofing participants or bypassing message policies.

⏰ Message reminders

Set a reminder on this device. Keep this page open for in-page reminders; browser notifications require permission.

🗂️ Chat organization

Personal pins and labels saved locally on this device. They do not change other users' inboxes.

🛡️ Scam & spam check

Quick local warning signals only; this is not an authoritative verdict or automatic moderation.

Compress a photo on this device before sharing to reduce data usage. The original file is not uploaded by this tool.

🧩 Features that need server/provider work

End-to-end encrypted private chats

Not enabled. This needs a vetted client cryptography protocol, key verification/recovery design, and a migration plan; simply encrypting a database column would not provide E2EE.

Scheduled messages

Not enabled for direct messages. Reliable sending requires a server scheduler/worker, server-side authorization, retry handling, and database migration.

Message translation and AI assistant

No translation or AI provider is configured in this project. These need a selected provider, server-side secret storage, privacy disclosures, and rate limits.

Chat polls and voting

Already present in SPIKE's existing feature-suite and live-poll database migrations; skipped here to avoid duplicating it.

Multi-device session management

Full device inventory/revocation needs server-side administrative support. Client-side sign-out only ends the current local session.
